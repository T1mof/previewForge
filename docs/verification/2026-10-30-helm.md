## Настоящий Helm lifecycle

Из созданного `.tgz`, а не из рабочей директории templates, установлен release
`forge-custom` в `previewforge-helm-system`. Установочный Namespace, TLS Secret
и canary ConfigMap созданы отдельно от chart.

1. PreviewEnvironment `helm-smoke` создал настоящий Namespace/Deployment/Service; приложение ответило HTTP. Имя Namespace вычислено из живого UID CR, controller owner reference проверен по API version/kind/name/UID до использования Namespace.
2. Запись от custom operator ServiceAccount в своё окружение разрешена, создание Service в чужом Namespace отклонено именно ownership webhook. Проверен runtime флаг identity, а не только отрендеренный текст.
3. Вторая установка отказалась принимать существующие ресурсы: `invalid ownership metadata`. UID/resourceVersion существующего ClusterRole не изменились.
4. Upgrade установил две реплики оператора с leader election и изменёнными ресурсами. Исправление drift приложения `3 → 1` подтверждено API и rollout. UID CR, его Namespace и Deployment приложения сохранились.
5. Rollback к revision 1 вернул одну реплику оператора, сохранив те же UID. История содержит revision 1/2/3, последняя deployed. Внешний TLS Secret сохранил UID.
6. Fixture CR удалён, финализатор завершился после полного удаления Namespace. После Helm uninstall сохранились UID/spec CRD и установочный Namespace; canary сохранил UID/resourceVersion. Managed ClusterRole и webhook исчезли. Fixture Namespace затем удалены отдельно, отсутствие проверено.
7. Тот же `.tgz` установлен в default namespace, затем прошли все прежние 19 сценариев, включая admission, HTTP/Ingress/PR-fixture, monitoring, resource controls, сетевую изоляцию, TTL и GC.

Helm не управляет пользовательскими CR, установочным Namespace или private TLS material.
CRD хранится в `crds/`: Helm сохраняет его и не обновляет автоматически при
upgrade/rollback. [Контракт установки и удаления](../HELM.md).

## Границы готовности

Chart рассчитан на один cluster-wide operator и Kubernetes 1.37.0; расширенная
version matrix остаётся отдельной задачей. Admission по умолчанию выключен,
как в `config/default`; guarded mode требует явного включения и существующего
TLS Secret/CA. Demo helper выдаёт сертификат на 48 часов. Постоянная ротация TLS,
доступность webhook и совместимые CRD schema upgrades — обязанности администратора.
Broad RBAC reads/CR writes и остальные ограничения [security model](../SECURITY.md)
сохраняются; это не hostile multi-tenancy.

Образ и Helm chart не публиковались в registry/OCI. Внешний PR workflow не
активирован; площадка/домен остаются отложенными. Следующий этап — нагрузочные
и отказные испытания, затем Kubernetes version matrix.
